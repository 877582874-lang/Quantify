# ARCHITECTURE — 系统架构规范

版本：v1.0（A2 阶段确立）
适用：Crypto Quant Research Platform 全部后续阶段。本文件是规范，不是实现说明；A2 阶段无业务代码。

## 1. 分层与模块边界

系统自下而上分为五层，依赖只能自上而下，禁止反向依赖与跨层直连：

1. **交易所适配层** `app/exchanges/`：只负责与交易所 API 对话（REST/WebSocket 的协议细节、签名、限频），不包含任何策略逻辑。
2. **采集层** `app/collectors/`：按计划拉取/订阅行情并原样落入 raw 区。采集与策略计算**彻底分离**：采集进程不做指标计算，策略进程不直接调交易所接口。
3. **存储与数据层** `app/storage/`、`app/data_quality/`、`data/`：负责原始数据、标准化数据、特征数据的读写与质量检查。
4. **研究层** `app/strategies/`、`app/backtesting/`、`app/risk/`、`app/evaluation/`：策略研究、回测、研究侧风险模型与评估。
5. **服务与展示层** `app/api/`、`app/services/`、`app/core/`：研究 API、后台服务编排与公共组件（配置加载、日志、时间工具）。

## 2. 数据流（单向）

```
交易所 API → collectors → data/raw（不可变）
                         → 清洗管线 → data/normalized → data/features
                         → strategies / backtesting / evaluation
```

- **原始数据不可覆盖**：清洗、修正、重采样只能读 raw、写 normalized/features，任何程序不得回写或删除 raw 原始记录；发现原始数据错误时以新增修正记录和质量标记处理，并在 data_quality 中留痕。
- 每条行情记录必须携带：交易所、交易对、时间戳（UTC）、数据类型（见 DATA_CONTRACT.md）。

## 3. 时间规范

- **存储与计算统一使用 UTC**（时间戳以 UTC epoch 毫秒或带 UTC 时区的 ISO 8601 存储）。
- 展示层（报表、面板）可以转换为北京时间（Asia/Shanghai, UTC+8），但转换只发生在展示层，不得污染存储层。
- K 线时间一律以 K 线**开始时间**标记，并注明周期。

## 4. 策略规范

- 每个策略必须有**唯一名称**（英文小写下划线，如 `trend_btc_ma_cross`）与**语义化版本**（如 `v1.0.0`），名称+版本构成策略的全局唯一标识。
- 策略按族分目录：`trend / mean_reversion / momentum / arbitrage / volatility`，一个策略一个目录，含其配置模板（放 `config/strategies/` 对应位置）与说明。
- 策略代码只能依赖存储层与 core 的公开接口，不得直接访问交易所、不得直接下单。

## 5. 实验规范

- 每次实验必须保存：**参数全集、数据范围（交易所/交易对/周期/起止 UTC）、代码版本（git commit 或版本号）、策略名称与版本、运行时间与环境版本（Python 与关键依赖）**，存放于 `experiments/configs/` 与 `experiments/results/`。
- 无上述元数据的回测/实验结果视为无效结果，不得进入评估与报告。

## 6. 回测规范

- 回测必须计入：**手续费、滑点、成交限制**（如最小下单量、价格/数量精度、流动性约束下的部分成交假设），参数必须显式记录在实验配置中。
- 必须支持**样本外测试**：数据集须按时间切分样本内/样本外，禁止随机打乱时间序列做切分。
- **不允许使用未来数据**：信号生成只能使用决策时点之前已到达的数据；财务/行情字段的可用时点以交易所实际发布时间为准。
- **回测结果不得直接认定为实盘收益**：报告必须标注其为历史模拟结果，并同时给出样本外结果与主要假设（手续费/滑点取值）。

## 7. 研究与执行隔离

- **交易执行模块与研究模块彻底隔离**：本项目（研究平台）不包含下单、撤单、仓位管理等执行功能，不保存可交易凭证。
- 未来如需执行系统，必须是独立项目/独立部署/独立凭证与独立审批流程，研究平台只以文件或 API 形式输出研究结论，不直接触发交易。

## 8. 部署形态（规划，A2 未实施）

- 容器化：Docker Compose 编排采集、研究 API、数据库等服务，同一内部网络互通。
- 对外暴露面最小化：仅 Caddy（80/443）对外，数据库与内部服务端口不映射公网。
- 凭证只经 .env 注入（权限 600），不进入镜像与代码仓库。
