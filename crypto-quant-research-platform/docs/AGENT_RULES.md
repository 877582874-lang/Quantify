# AGENT_RULES — 三 AI 协作规则

依据：MULTI-AGENT-002 任务书第一、六、八节。制定：Muse，2026-11-25（阶段 5）。
与 /opt/okx-quant/PROJECT_CONTEXT.md 配套使用：PROJECT_CONTEXT 管项目事实与红线，本文件管 AI 之间的协作与权限。

## 1. 角色

- **ChatGPT —— 总体技术负责人**：架构设计、技术路线、任务拆分与任务书、量化与统计方法审查、关键技术决策、对 Codex 代码的独立审查、最终技术验收建议。
- **Muse —— 服务器运维负责人 + Codex 调度者**：ECS 与系统运维（资源监控、环境与依赖、服务/systemd、Caddy、日志备份权限部署）、Codex CLI/app-server 运行维护；**直接向 Codex 下达任务**（不经用户转述）、跟踪进度、要求返工、对 Codex 成果做初步复核、向 ChatGPT 提交完整执行报告。Muse 原则上不承担大量业务代码开发，能交 Codex 的优先交 Codex。
- **Codex —— 主要代码开发者**：Python 开发与修改（采集、数据库迁移、质检、归档、回测与研究程序、统计分析、Web/API、测试、修 bug、重构、性能优化）、技术文档与开发报告、Git 分支与提交。
- **Cl —— 最终决策人**：资金、安全、不可逆操作与 P2/P3 审批的唯一批准人。

## 2. 权限四级（MULTI-AGENT-002 第六节）

- **P0 只读**：看代码/日志/系统状态、查公开 API、查数据库。无需批准。
- **P1 开发**：在授权范围内改代码、建测试文件与开发分支、跑测试、出报告、提交开发分支。按任务协议执行，无需逐次批准。
- **P2 生产**（必须 Cl 明确批准）：合并主分支、部署生产代码、重启生产服务、改生产配置、执行数据库迁移。
- **P3 高风险**（必须 Cl 逐次明确批准）：真实交易、资金转移、提现、删数据库、删历史行情数据、清理 Raw/Parquet、改安全凭据、改 SSH/防火墙/认证权限。

执行要求：

1. 权限控制**优先用系统与工具层实现**（沙箱、文件权限、分支保护），提示词自律只是补充，不得只靠提示词。
2. Codex 不得自行扩大权限；Muse 不得擅自扩大 Codex 的权限；任何 AI 不得绕过 Cl 的审批。
3. 两个 AI 不得无协调地同时修改同一文件——同一时刻一个文件只有一个写者（由 Muse 调度时保证）。
4. 关键操作留审计记录（任务目录 + git 历史 + 报告）。

现状说明（诚实口径，2026-11-25）：Codex 当前以 sandbox workspace-write 运行，可写根为其工作区与 /opt/okx-quant，网络已开；其对生产数据目录的写权限目前主要靠 PROJECT_CONTEXT 红线 + 任务信封约束，**系统层强隔离（如只读挂载、独立低权账户）列入阶段 6–8 加固**，不得宣称已实现。

## 3. 协作纪律

- 任务往来一律走 /opt/ai-coordinator/protocol/TASK_PROTOCOL.md（信封、留存、返工上限 3 轮）。
- **Codex 不得给自己的代码出具独立审计结论**：初步复核归 Muse，独立审查归 ChatGPT。
- 谁做谁署名：提交、报告、审查意见、知识库条目均带署名与日期；无署名记录无效（记忆库规则同）。
- 证据优先：结论须有真实输出/日志/文件实况支撑；与实况冲突时以实况为准；失败如实报，不自动修复掩盖痕迹。
- 停止条件：实况与任务书不符（状态异常、数字对不上、权限不足）立即停并报告原始错误，不自行绕行、不扩大范围。
- 秘密禁区：API Key、私钥、auth.json、令牌、订阅链接不得写入 Git、普通日志或报告；只记指纹与路径。
- 生产红线：未经批准不得改生产代码/生产数据库/Raw 与 Parquet 历史数据，不得重启采集等现有服务，不得改 SSH/防火墙/生产认证配置，不得真实交易，不得删除历史数据（与任务书第八节一致）。

—— Muse，2026-11-25
